# End-to-end tests

> [!WARNING]
> This suite creates and deletes metadata, changes group memberships through the app, creates and removes a SQL view, and installs and then uninstalls the app. Run it **only against a throwaway DHIS2 instance** that you can reset or recreate. Never run it against a play server, a shared test server or a production server.

## Getting a throwaway instance

Follow [DHIS2 in Docker](https://developers.dhis2.org/docs/tutorials/dhis2-docker/) on the developer portal. It covers `d2 cluster` and the Docker Compose file in dhis2-core. A demo database (for example Sierra Leone) is useful but not required: the suite seeds its own fixture.

## Running

You need Python 3, Playwright for Python and its Chromium:

```bash
pip install -r e2e/requirements.txt
python3 -m playwright install chromium
```

Build the app, then run the suite against your local instance:

```bash
pnpm build
mkdir -p e2e/results
DHIS2_URL=http://localhost:8080 DHIS2_USER=admin DHIS2_PASS=district \
RESULTS_DIR=$PWD/e2e/results APP_ZIP=$PWD/build/bundle/tool-group-set-manager-1.0.0.zip \
  e2e/run.sh
```

| Variable                   | Required | Meaning                                                            |
| -------------------------- | -------- | ------------------------------------------------------------------ |
| `DHIS2_URL`                | yes      | Instance base URL, no trailing slash                               |
| `DHIS2_USER`, `DHIS2_PASS` | yes      | A user with the `ALL` authority. No default for either.            |
| `APP_ZIP`                  | yes      | Absolute path of the built bundle to test                          |
| `RESULTS_DIR`              | yes      | Existing directory for `results.json`, screenshots and `e2e.log`   |
| `LABEL`                    | no       | Label for output and screenshot names; default: the server version |
| `APP_KEY`                  | no       | Default: the key the server reports for the installed app          |

Exit codes: `0` every test passed, `1` at least one test failed, `2` the suite could not run or could not clean up after itself (`results.json` then has an `error` field naming the stage). A failed test leaves a full-page screenshot `<label>-<test id>.png` in `RESULTS_DIR`.

## What it does

1. Deletes whatever an earlier, interrupted run left behind, as listed in the dataStore at `e2e-state/tool-group-set-manager`.
2. Installs `APP_ZIP` with `POST /api/apps` and finds its key in `GET /api/apps` by the manifest's name.
3. Seeds a fixture through the API. Every name starts with `E2E tool-group-set-manager <run id>`, and every object is listed in the state record, with a UID generated by the suite, before it is created:
    - a compulsory, data-dimension organisation unit group set with three groups (Alpha, Beta, Gamma);
    - a parent organisation unit under the first district of the user's hierarchy, with five children: one org unit in two groups (a conflict), two in none (missing), the rest in one group each.
4. Runs the tests in a headless Chromium. On 2.42 and later the app runs inside the global shell's iframe; on 2.41 and earlier it is served at the top level. The suite handles both.
5. Always cleans up: deletes the fixture, the app's History entries for the fixture's group set, and the usage SQL view if the suite installed it; then deletes the state record and uninstalls the app.

Every write the app makes is checked against the server through the API, not only in the UI, and then reverted through the app's own History. After each test the suite also restores the seeded memberships through the API, so a failed test does not change the next test's expected values.

## Tests

| Id                            | What it checks                                                                                                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dashboard-cards`             | The fixture's card shows its badges and conflict, missing and OK counts that match the API, and opens the group set                                                        |
| `freshness-refresh`           | A membership changed on the server behind the app's back shows up after Refresh                                                                                            |
| `drilldown-matrix-to-objects` | The overview matrix row for the parent counts 6 objects (2 missing, 1 conflict); its Total and Conflict cells drill into the matching objects                              |
| `search-objects`              | Search finds the fixture by run id and by name, finds the last org unit in load order (past the first page of rows), clears back to the full count and empties on no match |
| `single-assign-and-revert`    | Resolving the conflict by keeping one group is written to the server and to History, and reverting it in History restores the conflict                                     |
| `bulk-move-and-revert`        | Drilling into the Missing cell and bulk-assigning both org units to one group previews `+2 / -0`, writes both, and reverts through History                                 |
| `history-revert`              | History lists an assignment with its action, set and count; the revert dialog names the org unit; the revert is written and recorded                                       |
| `settings-sql-view-status`    | Settings shows each GSI SQL view and the usage view with a status that matches the server                                                                                  |
| `integrity-tab`               | The DHIS2 integrity tab opens and a check renders a result; skipped when the user has neither `ALL` nor `F_PERFORM_MAINTENANCE`                                            |
| `usage-view-install-remove`   | Settings installs the usage SQL view, the Usage tab reads it, and Settings removes it again; skipped when the view existed before the run                                  |
